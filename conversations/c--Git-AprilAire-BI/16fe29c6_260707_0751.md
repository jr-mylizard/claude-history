**Q2: Automated add/remove test on every sync**

Yes, and it's simpler than a dedicated endpoint. The sync fires when `should_be_allowed ≠ allowed_in_mosyle`. So you can prime a specific app for testing by manually setting `allowed_in_mosyle` to the opposite of what it should be — the next sync will correct it (adding or removing the CDA), and the run after that will find nothing to do. To make it flip every sync, you'd need it to keep alternating.

Two options:

**Option A — One-shot test (no code changes):** Pick one app that `should_be_allowed = true` for your iPhone, set its `ios_device_apps.allowed_in_mosyle = false`, trigger a sync, watch logs for "assigned CDA" + "Bounce". Repeat with `= true` on an app that should be false to test removal. Good for verifying the fix works once.

**Option B — A `test-flip-cda` edge function:** Takes `?device_id=&app_id=` and simply flips `ios_device_apps.allowed_in_mosyle` to the opposite of its current value, then triggers a sync inline. Every call toggles, so hitting it before each sync gives you alternating add/remove. Low code cost — want me to build this?
