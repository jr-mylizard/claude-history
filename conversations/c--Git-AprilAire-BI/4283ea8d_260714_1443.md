## What's already built for SMS

The repo has a **complete two-way SMS↔email relay** using the **Android SMS Gateway** app (sms-gate.app) running on a physical Android phone as the "local device" — plus **Resend** as the email leg. It's not Twilio/Telnyx (that's present only as disabled Supabase Auth boilerplate).

**Flow:**
- **Outbound (send-sms):** app inserts a `sms_messages` row → POSTs to `api.sms-gate.app/3rdparty/v1/messages` (Basic auth via `SMS_GATEWAY_USERNAME`/`PASSWORD`, targeting your phone via `SMS_GATEWAY_DEVICE_ID`) → phone sends the text → status updated to `sent`/`failed`.
- **Inbound SMS → Email (sms-webhook):** the Android Gateway app calls this webhook when a text arrives on the phone → row inserted into `sms_messages` → forwarded to `SMS_FORWARD_TO_EMAIL` via Resend, with `reply_to` set to `{sms_handle}@waxenua.resend.app` so a reply routes back correctly.
- **Email reply → SMS (resend-webhook):** Resend's `email.received` event fires → parses the `sms_handle` from the recipient address → looks up `sms_contacts` → fetches the email body → sends it back out as SMS via the same gateway API.
- **Contacts (export-sms-contacts):** generates a `.vcf` of `sms_contacts` so the phone's Contacts app can label incoming numbers.

**Tables:** `sms_contacts` (with auto-generated `sms_handle`) and `sms_messages` (`direction`: outbound/inbound; `status`: pending/sent/delivered/failed/received), defined in `supabase/schemas/10 Tables/107 SMS/` and migrated in `20260520000007_sms_tables.sql` + two follow-ups.

**Gap found:** `supabase/functions/.env.template` doesn't document `SMS_GATEWAY_USERNAME`, `SMS_GATEWAY_PASSWORD`, `SMS_GATEWAY_DEVICE_ID`, or `SMS_WEBHOOK_TOKEN`, even though all four are required by the code — a new dev copying the template would be missing them. CI already pushes these as branch secrets via `.github/workflows/set-branch-secrets.yml`.

No README/docs cover this — the only documentation is inline comments in each function file.
