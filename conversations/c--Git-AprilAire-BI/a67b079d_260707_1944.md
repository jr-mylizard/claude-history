How do I split an json array column into rows?

**Claude**

In Postgres, use `jsonb_array_elements` (or `json_array_elements` for the `json` type):

```sql
SELECT
  id,
  elem ->> 'key' AS value
FROM my_table,
jsonb_array_elements(my_column) AS elem
```

Or if it's a plain array of strings/numbers:

```sql
SELECT id, elem
FROM my_table,
jsonb_array_elements_text(my_column) AS elem
```

The comma in the `FROM` clause is an implicit `CROSS JOIN LATERAL` — each row fans out into one row per array element.

**You**

Can CDAs replace entire sections within the mobileconfig, so that the CDA could contain "key>allowAppInstallation
<false/>"

---

**Claude**

No — CDAs are string value substitutions only. They fill in a leaf value at a specific slot in the mobileconfig, like a bundle ID string. The profile template defines the structure statically; the CDA just provides the string that goes into a predefined position.

A mobileconfig plist is a typed XML format. `allowAppInstallation` expects a boolean element (`<true/>` or `<false/>`), not a string slot. Even if Mosyle allowed a CDA to contain `<key>allowAppInstallation</key><false/>`, the plist would either reject it (invalid type) or treat it as a literal string in the wrong context.

CDAs were designed for things like: bundle IDs, email addresses, server hostnames, VPN identifiers — all string leaf values. They can't inject structural plist elements or change a field's type.

The allow-list approach you already have is the right use of the mechanism. The App Store enable/disable stays as-is.
