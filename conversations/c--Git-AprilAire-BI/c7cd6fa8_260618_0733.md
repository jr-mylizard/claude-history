---

**Claude**

Don't use a real card — Stripe has the same concerns as Square about self-dealing, and you risk account flags or holds.

The good news is you don't need to. Since you'll be testing against the sandbox key, Stripe won't process any real money. Just use Stripe's built-in test card numbers:

- **Successful payment:** `4242 4242 4242 4242`
- **Requires authentication (3DS):** `4000 0025 0000 3155`
- **Declined:** `4000 0000 0000 9995`

Use any future expiry (e.g. `12/34`), any 3-digit CVC, and any ZIP. These only work in test mode — they'll be rejected in live mode, which is another reason to confirm the preview environment is on the `sk_test_` key before you test.

**You**

I want to test in production.  Because creating a cart succeeded in Sandbox but failed in production, I'm not convinced that checkout will work in production just because it did in sandbox.

---

**Claude**

That's a reasonable concern. Stripe is generally fine with a one-time self-charge for production verification — it's a well-known testing practice they support, unlike Square. The key is to keep it clean:

1. **Use the cheapest item in your catalog** — minimize the charge amount
2. **Refund yourself immediately** after the transaction confirms — Stripe Dashboard → Payments → find the charge → Refund
3. **Don't repeat it** — one successful end-to-end test is all you need; repeated self-charges are what triggers risk flags

The refund means you're out nothing but the Stripe processing fee (typically ~$0.30 + 2.9%), which is worth it for the confidence that production checkout actually works.
