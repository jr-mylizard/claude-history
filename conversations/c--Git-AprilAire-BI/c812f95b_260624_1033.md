**Claude**

You can't, unfortunately — the UI only shows connection names, not GUIDs. The GUID is an internal identifier not exposed in the search box.

The practical alternatives:

**Option 1 — Fabric REST API (most direct)**
```
GET https://api.fabric.microsoft.com/v1/connections/{connectionId}
```
You can call this from a browser while logged in, or via PowerShell with `Invoke-RestMethod` after getting a token. It returns the connection name and owner.

**Option 2 — Browse by process of elimination**
In **Manage connections and gateways**, filter by connection type:
- Look for a **Fabric / workspace** type connection → likely `198a2204-...`
- Look for a **Lakehouse** or **SQL Server** type → likely `a3086a63-...`
- Look for a **Power BI Datasets** type → likely `72dc2161-...`

There probably aren't many of each type, so the owner should be obvious.

**Option 3 — Check the pipeline in the Fabric UI**
Open the MASTER pipeline in the Fabric Data Factory canvas, click each activity, and look at the connection dropdown — it'll show the connection *name* for whatever ID is wired up. That's probably the fastest way to identify them without touching the API.

The Power BI REST API (`api.powerbi.com/v1.0/myorg/`) has gateway datasources but **not** Fabric connections — those are a different concept and live on the Fabric API (`api.fabric.microsoft.com/v1/`).

You don't need a full new collection though. Just add two requests to your existing Postman collection — the auth setup (token, base URL) is the same Azure AD flow you're already using:

**List all your connections (find by name/type):**
```
GET https://api.fabric.microsoft.com/v1/connections
```

**Get a specific connection by the GUID you already have:**
```
GET https://api.fabric.microsoft.com/v1/connections/198a2204-81f2-471f-a319-c39603296d24
```

The token scope needs to be `https://api.fabric.microsoft.com/.default` (or `https://analysis.windows.net/powerbi/api/.default` — Fabric accepts both). If your existing collection is already using the Power BI scope it should work without changing the token.
