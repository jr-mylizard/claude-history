`product_id` is the App Store numeric track ID (e.g., `302584613` for Kindle). Why were there so many issues with this deployment, and how can we avoid this in the future?

---

**Claude**

Three separate root causes stacked on top of each other:

---

**1. Timestamp version collisions (the first two failures)**

Both this branch and `dev` were developed in parallel, and independently happened to create migrations on the same days with the same counter (e.g., both created `20260527000000` on May 27). Supabase uses that timestamp prefix as the primary key in `schema_migrations`, so there's no room for two different files to share a slot.

**Prevention:** Before creating a new migration, pull dev and check what the latest version number is. If dev has `20260527000002`, start yours at `20260527000003`. Or just use a slightly later date or higher counter when you know you're working in parallel with dev activity.

---

**2. Non-idempotent migrations made the fix harder**

`staged_device_enrollments.sql` used `CREATE TABLE` without `IF NOT EXISTS`. That forced a code change (not just a rename) when resolving the collision. If it had been idempotent from the start, the rename alone would have been enough.

**Prevention:** Default to `IF NOT EXISTS` / `CREATE OR REPLACE` / `CREATE TRIGGER` → `CREATE OR REPLACE TRIGGER` in every migration. The cost is essentially zero and it makes every migration re-runnable — which matters any time you need to reorder, replay, or test against a partially-applied schema.

---

**3. The stripe schema guard checked the wrong column**

`20260606000001_vw_stripe_products.sql` already had a guard, but it checked for `stripe.products.metadata` (which exists on this branch) rather than `stripe.prices.currency` (which doesn't). The guard gave a false sense of safety.

**Prevention:** When writing a conditional migration that wraps a view or query, make the guard check a column that's actually *required by the query body*, not just any column from the schema. If the view selects `pr.currency`, the guard should be `IF NOT EXISTS (... column_name = 'currency')`.

---

**Underlying pattern:** This branch lived a long time without syncing to dev. The longer a branch diverges, the more likely these three issues are to collide simultaneously. Merging dev into the feature branch every week or two — rather than once at PR time — would have surfaced each conflict individually and in a much smaller context.
