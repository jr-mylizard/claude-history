## 1. Calendar — there's a direct template

The WeWeb calendar is literally `@fullcalendar/vue3` under the hood. For Next.js, the exact same library exists as `@fullcalendar/react` — same plugins, same config keys, same event fields. It's a near-verbatim port. The plugins already used are `daygrid`, `timegrid`, `list`, `interaction`, `multimonth`, and `luxon3` — all have React equivalents.

The data source is `vw_device_calendar` filtered by `device_id`, and events expose `event_start`, `event_end`, `title`, `color_hex`, `group_id`. The config maps directly. Calendar is the most visually complex piece but actually the least ambiguous to implement.

---

## 2. Confusing Datagrids

**Schedules Datagrid** — the `weekdays`, `Hour Start`, `Minute Start`, `Hour End`, `Minute End` columns are all non-editable. That means the datagrid is **read-only / display-only** for those fields. Editing must happen via a separate form elsewhere on the page (the checkboxes and hour/minute dropdowns visible in the variables). The "Delete" column has no `field` — that's a custom action button cell renderer.

**App Categories Datagrid appears twice** with identical config (`device_app_categories`, same 3 columns). One is shown in the "App Categories" tab, one presumably in another context. The "Schedule Name / Number" column has an empty `field: {}` — it's a WeWeb custom cell renderer. What that cell actually renders (a dropdown? a text?) isn't readable from the JSON. This is the one piece where I'd need to see the live WeWeb page to know.

**Website Categories Datagrid** — the `schedules` column maps to a field called `schedules` (plural). The `vw_dns_device_profiles_with_description` view probably returns this as a formatted string or array. Non-editable, so again it's display-only.

## 3. Other unclear things

**The schedule editing flow** — the page has weekday checkboxes, hour dropdowns, and minute dropdowns as separate controls. But there's also a `selectedSchedule`, `selectedScheduleId`, `selectedScheduleStart/End`, `selectedScheduleWeekdays` variable set. The picture is: user clicks a row in Schedules Datagrid → variables populate → the form controls below show that schedule's data for editing → user saves. But the actual save workflow has 26 actions and I can't fully trace which Supabase calls it makes without reading it deeply.

**`device_calendar` vs `vw_device_calendar`** — two separate collections in the page. The calendar uses `vw_device_calendar`. `device_calendar` appears unused by the calendar itself; it may feed some other element or be legacy.

**`App_Group_Not_Set` defaults to `True`** — something on the page is conditionally shown/hidden based on whether the app group has been configured. Probably a banner or warning, but which element is gated on it isn't visible from the JSON.
