Yes exactly. The call chain is:

**You**

Does it use .ml_call_edge_function?  That's the helper function I'd been using otherwise.

---

**Claude**

No — and it can't. `.ml_call_edge_function()` returns `trigger` and uses trigger-specific variables (`TG_ARGV`, `TG_OP`, `OLD`, `NEW`, etc.), so it only works when called by a database trigger. It can't be invoked as a regular function from pg_cron or another SQL function.

That's why `.ml_post_enrollment_ios()` duplicates the vault lookup + `net.http_post` pattern directly. If you find yourself creating more cron-driven edge function callers, it might be worth extracting a non-trigger helper (e.g., `.ml_http_post_edge_function(url_path, payload)`) to share that logic — but for now the duplication is intentional.
