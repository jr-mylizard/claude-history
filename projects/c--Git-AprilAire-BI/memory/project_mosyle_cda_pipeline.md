iOS app visibility pipeline (verified end-to-end 2026-07-13): ios_device_apps → sync-apps-and-websites cron (iOS minutes 1-59/3) → CDA assign/create in Mosyle → bounce device group 14 → Mosyle re-renders mylizard.mobileconfig (repo: MyLizard-Supabase/mosyle/) with CDA variables → whitelist controls app VISIBILITY only (never installs/uninstalls).

Key findings:
- **Mosyle render race**: profile variables render when device is re-added to group 14. Bouncing <~5s after CDA assigns misses the new values (silent). Evidence isolated the cause to unsettled ASSIGNS, not the remove→add gap (a 0.7s gap rendered correctly when values were 1.5h old). Fixed in bounce-ios-profile.ts (CDA_SETTLE_MS=30s wait BEFORE the bounce; remove/re-add stays back-to-back because the device has NO whitelist profile between them — all apps visible) — pending deploy. 30s is not a measured minimum; 3s fails, could likely tune to 10–15s.
- **Force-push in Mosyle UI re-sends the CACHED render**; only a group remove/re-add re-renders variables.
- **lpad truncates**: Postgres lpad('12501',4,'0')='1250'. Fixed with greatest() in schemas/20 Views/204 iOS/20401 vw_desired_mosyle_cdas_state.sql + its pgTAP test — pending deploy.
- **mobileconfig covers %custom_AA0001%–%custom_AA9999% only** (generated, not a Mosyle limit). ios_apps id sequence has jumped past 12500 so ALL new apps get 5-digit ids → invisible. Slot-based redesign discussed (fixed pool of per-device slot CDAs instead of one CDA per app) — CDA values are already per-device, so catalog size becomes unlimited.
- **Frontend "Installed" badge is wrong**: it means "row exists in ios_device_apps" (added to catalog), not device state. add-apps NEVER installs anything on iOS — it opens an App Store window (2h for paid + email) and the user installs manually. Uninstalls are never reconciled back into the DB.
- **Mosyle "tombstoned" CDA ids are transient** — Audible custom_AA4340 blackholed creates for a day (create/assign return success, nothing persists), then worked. Read-back verification is the only trust mechanism.
- CDA *names* in Mosyle are stale from an old app-id numbering — only UniqueID and Value are trustworthy. Mechanism (confirmed by 2026-07-13 screenshot: names and values BOTH alphabetical but offset): names are only written at CDA creation; assign calls update the value only, and the update API is never used (it lowercases values). After any ios_apps renumbering, values track the new id meaning while names keep the old one. Slot-model CDA names are deliberately semantic-free ("App slot NNNN").
